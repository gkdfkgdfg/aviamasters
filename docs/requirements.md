## Проект ИС склада канцелярских товаров

### 1. Цель и задачи
- **Цель**: обеспечить учёт, контроль остатков и движение канцелярских товаров малого предприятия, а также автоматизировать оформление заказов поставщикам и выдачу товаров сотрудникам.
- **Основные задачи**:
  - централизованное хранение данных о номенклатуре, поставщиках, заказах, приходах, расходах и сотрудниках;
  - поддержка инвентаризаций, контроля минимальных остатков и генерация заявок на пополнение;
  - формирование аналитической отчётности по категориям товаров, поставщикам, периодам.

### 2. Роли пользователей
- **Кладовщик**: управление складскими операциями (приход, расход, инвентаризация), просмотр остатков.
- **Менеджер по закупкам**: работа с поставщиками, оформление заказов, контроль поставок.
- **Бухгалтер/аналитик**: формирование отчётов и контроль движения средств.
- **Системный администратор**: управление учетными записями, настройка справочников.

### 3. Основные бизнес-процессы
1. **Приёмка товаров**
   - создание заказа поставщику;
   - подтверждение поставки и формирование приходного ордера;
   - обновление остатков на складе.
2. **Выдача товаров сотрудникам**
   - оформление расходного ордера с указанием подразделения и получателя;
   - резервирование и списание остатков.
3. **Инвентаризация**
   - фиксация фактических остатков;
   - выявление расхождений, формирование корректировок.
4. **Контроль минимальных остатков**
   - автоматическое отслеживание товаров, опустившихся ниже порога;
   - формирование предложений по заказу.

### 4. Функциональные требования
- управление справочниками (товары, категории, единицы измерения, поставщики, подразделения);
- оформление заказов поставщикам, приходных/расходных ордеров;
- учёт движения и текущих остатков по складам;
- ведение истории цен поставщиков;
- планирование и фиксация инвентаризаций;
- отчётность (остатки, движение, просроченные поставки, списанная продукция);
- аудит действий пользователей (журнал событий).

### 5. Нефункциональные требования
- платформа: ASP.NET Core 9.0 (Minimal API или MVC) + PostgreSQL 16;
- архитектура: модульная (слой API, слой приложения, слой доступа к данным);
- авторизация: JWT + ролевая модель;
- журналы доступа и операций в Elastic Stack / текстовые логи (опционально);
- возможность контейнеризации (Docker Compose для приложения и БД);
- резервное копирование БД средствами PostgreSQL (`pg_dump`).

### 6. Структура данных (ключевые сущности)
- **Product**: наименование, SKU, категория, единица измерения, минимальный остаток, цена закупки.
- **Supplier**: название, контакты, условия поставки.
- **WarehouseStock**: ссылка на товар, склад, текущий остаток, резерв.
- **InboundOrder**: заказ поставщику, список позиций, статус, даты.
- **InboundShipment**: фактическая поставка по заказу, документ прихода.
- **OutboundOrder**: выдача товаров, получатель, подразделение, причина.
- **InventorySession**: инвентаризация, дата, ответственный, статус.
- **InventoryAdjustment**: корректировки остатков по итогам инвентаризации.
- **UserAccount**: учётная запись, роль, активность.
- **AuditLog**: журнал действий.

### 7. Диаграммы
- **ER-диаграмма** (Draw.io / StarUML): описывает связи между сущностями (Product–WarehouseStock, Supplier–InboundOrder и т.д.).
- **Диаграмма вариантов использования**: роли и основные сценарии взаимодействия.
- **Диаграмма последовательности**: типовой цикл заказа и прихода товара.

### 8. Технологический стек и сервисы
- Backend: ASP.NET Core 9, C# 12, MediatR, FluentValidation, AutoMapper.
- ORM: Entity Framework Core (Npgsql provider).
- Аутентификация: ASP.NET Identity + JWT.
- Логи: Serilog + Sink (консоль/файл), опционально Seq.
- Тесты: xUnit + Bogus (фиктивные данные).
- Документация API: Swashbuckle (Swagger UI).
- CI/CD: GitHub Actions (сборка, тесты, публикация контейнеров на GHCR).

### 9. План работ (укрупнённо)
1. Анализ и детализация требований.
2. Проектирование базы данных и интеграционных сценариев.
3. Настройка решения .NET, подключение PostgreSQL.
4. Реализация модулей: справочники, складские операции, отчётность.
5. Настройка аутентификации и аудита.
6. Тестирование (юнит, интеграционные, нагрузочные по необходимости).
7. Подготовка эксплуатационной документации и инструкций по резервному копированию.

### 10. Отчётность и визуализация
- Экспорт данных в Excel (файлы Excel или CSV) для стандартных отчётов.
- Интеграция с Power BI: подключение к PostgreSQL, создание дашбордов по остаткам и движениям.
- Шаблоны отчётов: «Остатки по категориям», «Заказы поставщикам», «История выдачи по подразделениям».

### 11. Риски и меры снижения
- **Риск**: нетопорная синхронизация при работе нескольких пользователей. **Мера**: блокировки на уровне БД, оптимизация транзакций.
- **Риск**: сбои оборудования. **Мера**: регулярные бэкапы и тест восстановления.
- **Риск**: человеческий фактор при инвентаризациях. **Мера**: журналирование, двухэтапное подтверждение корректировок.
- **Риск**: рост номенклатуры. **Мера**: горизонтальное масштабирование БД, оптимизация запросов.
